# Knowledge Center V2 自适应知识治理

本阶段在 Knowledge Engine V2 已有的“真实反馈质量闭环”和“人工纠正聚类修订候选”基础上，增加统一治理队列以及修订前后效果评估。

## 目标

Knowledge V2 不再只负责“存储、召回、直答和学习”，还持续把需要人工处理的知识问题集中暴露出来：

- 低质量知识
- 质量观察知识
- 同一事实键下的生产知识冲突
- 待复核修订候选
- 同一知识出现多个待复核候选
- 高风险/普通知识长期未人工验证
- 长期未使用且可能已经废弃的知识
- 因原知识变化而过期的修订候选
- 修订应用后真实效果明显退化、达到回滚建议阈值的知识

所有生产数据修改仍由人工显式触发。治理扫描本身只读，不会自动修改、删除、停用或回滚知识。

## 治理入口

Knowledge Center 顶部新增 `治理` 按钮。

治理窗口包含两个页签：

### 治理队列

统一展示：

- 优先级：紧急 / 高 / 中 / 低
- 治理项类型
- 知识标题和类型
- 命中次数
- 当前质量分
- 最近人工验证时间
- 触发治理的真实证据
- 推荐处理方式

支持搜索和按治理类别过滤。

人工动作：

- `生成修订候选`：继续使用真实人工纠正聚类，不让 AI 编造业务事实。
- `打开修订`：进入上一阶段的修订候选复核窗口。
- `确认仍有效`：人工核对后仅刷新 `LastVerifiedAt`，不改答案。
- `停用所选`：显式确认后将知识设为 `Enabled=false / Status=disabled`，不删除审计记录。

### 修订效果

对已经人工应用的修订，按修订应用时间切分真实反馈：

- 修订前 30 天
- 修订后最多 30 天

比较指标：

- 本地知识真实发送次数
- 买家/人工确认次数
- 人工纠正 + 撤回负向证据
- 修订前负向率
- 修订后负向率

发送失败不作为知识质量负向证据，因为它属于传输链路故障。

## 回滚建议

修订后至少有 3 次有效发送后才进入效果判断，避免小样本误判。

达到以下条件时产生 `建议回滚`：

1. 修订后至少 2 次真实负向证据；
2. 修订后负向率至少 25%；
3. 且比修订前负向率至少高 15 个百分点。

这是“建议”，不是自动回滚。

人工点击 `回滚所选修订` 后还需要 Yes/No 二次确认。

## 安全回滚保护

回滚只允许在“当前知识答案仍然等于该修订的 ProposedAnswer”时执行。

如果修订之后知识又被人工编辑，系统会拒绝自动回滚，避免把后续人工修改覆盖掉。

如果当前答案已经等于修订前的 OriginalAnswer，则效果页显示为“已恢复原答案”，不会重复回滚。

回滚成功后：

- 恢复修订审计记录中的 `OriginalAnswer`
- 更新 `LastVerifiedAt`
- 通过正式 Knowledge V2 Repository 保存
- 立即刷新结构化索引
- 原修订候选和证据仍保留在 revision 审计数据库中

## 验证过期规则

治理扫描目前使用固定保守阈值：

- 普通知识：180 天未验证进入治理队列
- 高风险知识：60 天未验证进入治理队列

高风险包括已有 `RiskLevel=high/critical`、安全边界知识以及命中 Knowledge V2 高风险语义规则的内容。

## 长期未使用规则

知识有效、不是学习候选，并且：

- 没有有效使用记录；
- 最近创建/更新/验证时间距今超过 120 天；

则进入低优先级 `长期未使用` 治理项。

系统不会自动删除它，只提示人工确认是否仍有业务价值。

## UI 初始化修复

上一阶段新增的 `修订` UI Bridge 已有完整实现，但没有独立 App bootstrap。

本阶段增加统一 bootstrap，在 App 初始化时同时启用：

- `KnowledgeV2RevisionUiBridge`
- `KnowledgeV2GovernanceUiBridge`

因此 `修订` 和 `治理` 两个入口都能稳定挂载到 Knowledge Center 顶部工具栏。

## 构建兼容

仓库仍使用 .NET Framework 4.8 + legacy csproj。新增 `src/Bot/Directory.Build.targets` 将治理 Service、UI 和 bootstrap 显式加入普通 Bot 项目以及 WPF `*_wpftmp` 临时项目，避免 XAML 临时编译阶段缺少类型。

## 后续方向

下一阶段可继续增加：

- 治理动作独立审计表和历史时间线
- 可配置的验证过期阈值
- 商品/SKU 生命周期触发的知识过期机制
- 云端多店铺治理汇总
- 修订 A/B 或灰度验证
- 自动生成“需要人工确认”的治理日报，但仍不自动修改生产知识
