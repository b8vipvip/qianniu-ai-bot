# Knowledge V2 自适应治理上线检查

## 自动化验证

合并前必须通过：

- API control plane CI
- Windows CI (Debug/x64)
- Windows x64 release build
- repository static tests

## 客户端验收

升级后打开 Knowledge Center：

1. 顶部同时能看到 `质量`、`修订`、`治理` 入口。
2. `治理` -> `治理队列` 能加载当前店铺数据，切换过滤条件不会影响其他店铺。
3. `生成修订候选` 只生成待复核候选，不自动修改正式知识。
4. `确认仍有效` 必须二次确认，只刷新 `LastVerifiedAt`。
5. `停用所选` 必须二次确认，停用后知识退出生产直答但仍保留记录。
6. `修订效果` 能看到已应用修订的前后 30 天样本统计。
7. 样本少于 3 次时只显示观察，不给出回滚建议。
8. 达到退化阈值时显示 `建议回滚`。
9. 回滚必须二次确认，并且当前答案已被后续人工修改时必须拒绝覆盖。
10. 回滚成功后当前答案恢复到修订前答案，Knowledge V2 索引立即刷新。

## 多店铺隔离

治理扫描、质量数据、修订候选、知识 Repository 均以 seller / ShopContext 进入现有店铺隔离链路。上线验收应至少使用两个店铺确认：

- A 店铺的治理项不出现在 B 店铺；
- A 店铺确认/停用/回滚不会修改 B 店铺数据库；
- 切换店铺后治理窗口重新读取对应 seller 数据。

## 生产观察

上线初期重点观察日志关键字：

- `Knowledge V2治理：人工确认知识仍有效`
- `Knowledge V2治理：人工停用知识`
- `Knowledge V2治理：人工回滚修订`

如果出现回滚拒绝提示，应先检查知识是否在候选应用后被人工再次修改；该拒绝属于预期的 stale-write 保护，而不是失败。
