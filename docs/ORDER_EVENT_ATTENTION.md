# 新订单识别、结构化订单信息与空闲自动切换

本功能不依赖淘宝开放平台授权，使用现有千牛消息、后台通知、远端聊天历史和安全会话切换能力。

## 五层架构

### 1. 结构化订单卡片解析

`OrderCardParser` 会先把千牛消息对象序列化成 JSON，并递归读取订单字段；可识别：

- 订单号；
- 商品 ID、标题；
- SKU ID、规格；
- 数量；
- 订单金额、实付金额；
- 交易/付款状态；
- 创建时间、付款时间；
- 商品链接和图片链接；
- 创建、付款、关闭和退款申请事件。

字段名不匹配时，才使用可见卡片文字和正则表达式兜底。原始卡片 JSON 不写日志、不持久化，只保存 SHA-256 哈希用于诊断和去重。

### 2. OrderEventHub 统一去重

所有识别到的订单事件都进入 `OrderEventHub`，去重键为：

`seller + orderId + eventType`

创建订单和付款成功属于不同事件；同一订单卡片由详细消息和远端历史重复发现时只处理一次。

状态保存在：

`%LocalAppData%\QianniuAiBot\data\order-event-state.json`

只保留最近 30 天、最多 2000 条结构化事件。

### 3. BotActivityCoordinator 空闲判定

自动切换前检查：

- 是否正在合并或回复买家消息；
- 是否正在分析图片；
- 是否正在生成或发送下单自动消息；
- 是否正在补抓后台消息；
- 新消息处理和发送互斥锁是否空闲；
- 千牛输入框是否为空；
- 客服最近是否发送消息或切换会话；
- 人工操作保护时间是否结束。

任何一项不满足都不会强制切换，而是继续留在待处理队列。

### 4. NewOrderAttentionQueue

新订单按以下顺序排队：

1. 已付款优先；
2. 事件时间较早优先；
3. 入队时间较早优先。

空闲状态连续确认两次后才会调用 `OpenChat`，随后循环读取 `GetCurrentConversationID`；只有确认当前千牛会话确实是目标买家，才更新 Bot 当前会话。

单个订单最多等待 30 分钟；连续无法确认会话时保留右侧任务卡并停止自动抢占。

### 5. 右侧订单摘要

识别新订单后，右侧会显示“新订单待处理”卡片，包括已解析出的：

- 买家；
- 订单号；
- 商品；
- 规格；
- 数量；
- 金额或实付；
- 状态；
- 时间；
- 来源。

卡片状态会显示等待原因、自动切换成功、切换失败或下单自动消息发送结果。

## 设置

入口：

`设置 → 功能设置 → 自动回复规则 → 买家下单后自动发送`

新增：

- 当前无任务时自动切换到新下单买家，默认开启；
- 人工操作保护，默认 12 秒，范围 3–120 秒；
- 最短自动切换间隔，默认 5 秒，范围 2–60 秒。

订单识别与自动切换独立于“下单后自动发送”开关。关闭下单自动消息后，仍会识别订单、显示摘要并在空闲时切换；只是不向买家自动发送预设消息。

## 检测通道

当前无需授权的通道：

1. 普通买家消息中的订单卡片；
2. 千牛后台新消息通知；
3. 详细消息缺失时，打开目标会话并调用 `im.singlemsg.GetRemoteHisMsg` 补抓最近 30 条历史；
4. 远端历史中的系统订单卡片使用同一结构化解析器识别。

由于不同千牛版本的卡片字段可能不同，未知字段会被递归扫描，但不会记录原始敏感数据。真实订单测试后可根据已解析结果继续补充字段别名。
