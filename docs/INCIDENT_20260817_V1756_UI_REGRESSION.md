# 2026-08-17｜1.1.756 设置界面更改在 1.1.758 中未稳定显示

## 现象

1.1.756 合并了“消息通知 -> 转人工策略”及“把启用转人工规则移动到转人工策略页面”的更改，但用户升级到 1.1.758 后，统一设置窗口左侧仍显示“消息通知”。

## 根因

不是 1.1.758 丢失了 1.1.756 的提交。`bot-v1.1.758` 是 `bot-v1.1.756` 的后继版本；问题在于 1.1.756 的 UI 改动主要放在 `BotUpdateHandoffSettingsUi.Fast.cs` 的 Loaded 事件运行时桥接中，而统一设置窗口 `WndOption.BuildSettingsPages()` 仍然硬编码：

- 页面标题：`消息通知`
- FeaturePage：`消息通知`

因此在 `FeatureSettingsOptionsControl` 尚未真正 Loaded 时（例如打开设置后停留在“关于与更新”等页面），运行时桥接根本没有机会修改已经构建的导航项，用户会直接看到旧名称。这个实现也把关键 UI 结构迁移依赖于运行时 VisualTree/Loaded 时序，稳定性不足。

## 修复原则

关键设置结构不再依赖 Loaded 事件补丁：

1. `WndOption.BuildSettingsPages()` 直接以“转人工策略”构建导航。
2. `FeatureSettingsOptionsControl` 构造时直接把底层 Tab 重命名为“转人工策略”。
3. 构造阶段直接把启用转人工规则、关键词和工作时间转人工话术从自动回复规则移动到转人工策略页面。
4. 旧“消息通知”仅作为 `NavigateTo` 的兼容别名，不再作为用户可见页面名称。
5. 增加静态回归测试，要求主设置代码本身包含新页面名称和迁移逻辑，禁止只测试运行时桥接补丁。

## 相关功能核对

同一 1.1.756 版本中的以下逻辑并未在 1.1.758 被回退：

- 固定首条咨询/下班回复在消息 quiet-delay 和上下文合并之前执行。
- 下单自动回复仍在普通 buyer burst enqueue 之前处理。
- 客户端后台更新发现改为服务端 SSE 主动通知。
- 外部进程 watchdog 用于 Bot.exe 意外退出后的拉起。

本次事件针对的是“代码已合并但 UI 修改依赖 Loaded 补丁，导致用户可见结果不稳定”这一实现缺陷。
